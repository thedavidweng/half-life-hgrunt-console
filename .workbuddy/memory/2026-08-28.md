## HECU Grunt Console — 词标签「点选删除」能力

需求：输入框（react-tag-input）里的词可拖拽排序，但删除只能从尾部退格，需要支持选中中间任意词后删除。

实现（最小改动）：
- `src/App.js`：新增 `selectedIndex` state；接上库自带的 `handleTagClick` prop 做点选/反选；在 `.tag-input-wrapper` 上用**捕获阶段** keydown 监听拦截 Backspace/Delete/Esc（ReactTags 默认只删最后一个 tag，必须在 document 冒泡到 React 合成事件之前 `stopPropagation`）。
- 选中态通过给 tag 对象挂 `className`（`ReactTags__tag--selected`，由 Tag 组件渲染到 `.tag-wrapper`）实现，渲染时派生 `decoratedTags`，不污染 state。
- `handleDrag` 改为从 `this.state.tags` 取被移动的词（避免把派生的 className 写回 state）。
- `src/index.css`：选中态用「凹陷」斜角（上左 `#1f2719` / 下右 `#687360`，背景 `#2a3520`），沿用 `.history` 的凹槽视觉语言，不产生布局位移。

## GitHub Pages 站点 404 排查（站点从未发布成功）

现象：https://thedavidweng.github.io/half-life-hgrunt-console/ 返回 GitHub Pages 的 "Site not found"。

排查路径（可直接复用）：
1. `gh api repos/<o>/<r>/pages` → 看 `build_type` 是否为 `workflow`、`status`；`gh api .../pages/builds` 为 `[]` 说明从未成功发布。

根因（共 3 个，前 2 个此前已被并行会话修掉）：
1. **`.github/workflows/deploy.yml` 监听 `branches: [main]`，但默认分支是 `master`** → 推送从不触发，只有手动运行过 4 次。已改为 `master`，现在推送会自动部署。
2. 构建失败（CRA 在 CI 下把 ESLint warning 当 error + webpack4/Node 的 OpenSSL 报错）→ 已由 `530802d`/`65c180d`/`3fc77f7` 修复。
3. deploy 阶段 `Failed to create deployment (status: 404) Ensure GitHub Pages has been enabled`：用 `curl -X PUT -d '{"build_type":"workflow"}' .../pages`（返回 204）重新确认 Pages 构建方式后恢复。注意 `github-pages` environment 是首次部署时自动创建的，可能与首次部署请求存在竞争，若再出现可先重跑一次。

## 上游 PR #18 的 4 个 Netlify 检查失败（已修）

4 个失败检查（Header rules / Pages changed / Redirect rules / deploy-preview）其实是**同一次构建失败被 Netlify 拆成 4 个检查上报**。日志在 Netlify 侧需登录，改为本地复现：

```
CI=true SKIP_PREFLIGHT_CHECK=true NODE_OPTIONS=--openssl-legacy-provider npm run build
```
关键是 `CI=true`——Netlify 默认会设置它，而 `react-scripts` 在 CI 下把 ESLint warning 当 error。

报错：`src/vox.js` Line 686 `'buffer' is defined but never used  no-unused-vars`。但 `buffer` 在 for-of 循环体里明明被用了 → 是 `eslint-config-react-app` + `babel-eslint` 的**误报**。
佐证：本仓库的 `hgrunt.js`（同一份代码改名而来）里，`65c180d` 先把 `buffer` 改名成 `buf`、**无效**，`3fc77f7` 加 `// eslint-disable-next-line no-unused-vars` 才消掉。
修法：在 `for (const buffer of buffers) {` 上方加同样的 disable 注释（`feat/select-word-to-delete` 分支，单独 commit）。修复后 `exit=0`，4 个检查全绿，预览站 https://deploy-preview-18--half-life-vox.netlify.app 正常且含新交互。

复用要点：
- Netlify 多检查失败先看是不是同一个 deploy 失败；`gh api repos/<o>/<r>/commits/<sha>/check-runs -q '.check_runs[].output.summary'` 能看到 "Deploy failed" 但拿不到日志。
- 上游无 `netlify.toml`（构建配置在 Netlify UI），`.node-version` = v16.20.2。
- 复现外部 CI 失败最快的方式：按对方的环境变量在本地跑一次构建。

## 后续调整（08-28 15:08）

- **问题 1：点选 tag 时不该出现候选词列表（因为没在输入）**
  - 把 `minQueryLength` 从 `0` 改成 `1`，只有真正输入时才展示建议；同时新增 `handleInputChange`，一旦用户开始输入就自动清除当前 tag 选中态。
- **问题 2：拖拽时插入位置不够清晰**
  - `react-tag-input` 在拖拽时会把被拖 tag 的 DOM 透明度设为 0，并实时重排 tags。我们在 CSS 里把这个隐藏的 tag 强制显示为「虚线幽灵」占位，并在左侧加一条白色竖线（`box-shadow: -2px 0 0 ...`，无布局位移），标示它即将插入的位置。
  - 为 `.ReactTags__tag` 加了 `position: relative` 作为阴影定位基准。
- **问题 3（关键坑）：拖拽占位标记只在原始位置出现，移动后消失**
  - 根因：`ReactTags.getTagItems()` 的 key 是 `tag.id + '-' + index`。一旦重排，所有 key 全变 → 每个 tag 组件**全部卸载重建** → 正在拖的那个 DOM 节点被销毁，react-dnd 的 `isDragging` 丢失，再也没有元素带 `opacity: 0`，依赖内联样式的 CSS 选择器（`.tag-wrapper[style*="opacity: 0"]`）自然全部失配。
  - 解法：不依赖库的 `isDragging`，改为在 App 里自己追踪「被拖词当前下标」`dragIndex`：
    - `dragstart`（document 级）时用 `closest('.ReactTags__tag')` + `querySelectorAll` 求出原始下标；
    - `handleDrag(tag, currPos, newPos)` 里把 `dragIndex` 更新为 `newPos`；
    - `dragend` / `drop`（都挂 document，因为源节点中途已被移除，事件可能不会冒泡经过 wrapper）时置回 null；
    - render 时给该下标的 tag 加 `className: 'ReactTags__tag--dragging'`，CSS 用这个 class 画虚线幽灵 + 左侧白线。
